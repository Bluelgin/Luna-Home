# Luna 记忆行为准则（设计与验收）

nanobot 已有当前会话、压缩历史、USER.md / SOUL.md / memory/MEMORY.md 与 Dream。本文件是**项目政策与人工审查清单**，不会因为存在于 GitHub 就自动注入模型。有效交互规则已压缩写在 `SOUL.md`，其余由 nanobot 现有系统处理。

## 三个层次

1. **即时上下文**：当前问题、最近一段聊天，允许随话题衰减，优先节省 Token。
2. **可检索历史摘要**：项目决定、跨天未完成的事，在请求与其相关时调用；不永久注入整份聊天记录。
3. **长期事实**：明确同意保存的称呼/偏好、用户多次确认的长期项目方向及不再适用的旧决定。一次玩笑不是永久事实。

## 分类约定

- `preference`：用户主动表示的风格偏好，例如“喜欢呆萌但做事靠谱”。
- `project_decision`：确认过的仓库路径、PR 决策、架构边界和取舍。
- `interaction_pattern`：经过重复确认的称呼和对话习惯。
- `temporary`：今天临时安排和刚发生的状态，不默认永久保存。
- `sensitive`：私密健康、身份和第三方资料等，默认不记入长期事实，除非用户明确决定保存且确有必要。

## 真实性与纠正

- 有不确定性时用“好像记得……要不要我再确认？”；**禁止凭空制造过去一起经历的情节**。
- 用户指出错误，应更正旧条目而不是新添一条互相矛盾的记忆。
- 用户要求忘记时，先解释当前能清理的范围与备份限制，不虚报已彻底删除；尤其原始会话、Dream、Git 版本记录、系统备份都是不同的存储层。
- 不允许 Dream 自动重写 Luna 人设中的核心边界（AI 身份、诚实、可靠、不依附），普通偏好可以演化但不可改变核心约束。
- 不记“用户每次发消息都很喜欢我”之类推断，不把拟人化互动升级为确认的亲密关系事实。
